## 一、目录结构

轻量三级分类，目标是用户手动打开目录时一眼可辨，不追求刮削器那套完整元数据体系。

```
媒体库根/
├── 电影/片名 (年份)/片名 (年份).扩展名
├── 剧集/片名 (年份)/Season NN/片名 SNNENN.扩展名
├── 动漫/片名 (年份)/Season NN/片名 SNNENN.扩展名
└── 其他/片名 (年份)/...
```

- 一级目录由 `--type` 决定，取值 `movie` / `tv` / `anime` / `other`
  （分别对应 `电影` / `剧集` / `动漫` / `其他`）。
- 二级目录是「片名 + 年份」，年份来自资源名解析结果；解析不到年份时省略
  `（年份）`，**不要**用 `未知`、`-1`、当前年份之类的占位值填充——占位年份会让
  同一部片在不同时间归档到不同目录。
- 剧集与动漫多了 `Season NN` 一层，与电影区分开，避免单集文件与整片电影混在同一层。

## 二、文件名格式

| 类型 | 目标路径 |
|---|---|
| 电影 | `电影/片名 (年份)/片名 (年份).mkv` |
| 剧集 | `剧集/片名 (年份)/Season 01/片名 S01E01.mkv` |
| 动漫 | `动漫/片名 (年份)/Season 01/片名 S01E01.mkv` |

- 季集号固定补零：季 2 位（`S01`）、集 2 位（`E01`）；集号超出 99 时按实际位数，
  不截断。
- **只有拿到集号才用 `SxxExx` 格式**。集号为 `None` 时一律走电影的「片名 (年份)」
  形式——整季合集、OVA 合集这类没有单集概念的文件属于此类。
- 有集号但无季号时，季按第 1 季处理（`Season 01`），并在给用户的报告里说明这一假设。
- 扩展名沿用源文件的小写形式；无法识别扩展名时按 `.mkv` 处理。
- 片名用解析器从资源名提取的结果，**不含**画质、编码、发布组等技术标签，
  也不含 `电影`/`高清`/`未删减`/`中字` 之类噪声词。

## 三、路径片段清洗规则

每个路径片段（片名、目录名）都过一遍清洗，规则固定且不可绕过：

1. 非法字符 `< > : " / \ | ? *` 一律替换为 `_`。
2. ASCII 控制字符（码点 < 32）替换为 `_`。
3. 去掉首尾的空格与点号。
4. 清洗后为空、`.` 或 `..` 时，统一改为 `unnamed`。

**为什么这么严**：这些片段最终会拼成落盘路径。`/` 或 `..` 若原样保留，就等于让
资源名里的内容直接操纵文件系统结构；跨平台文件名还受 Windows 的字符集限制，
在 Linux 上放行的名字可能到 Windows 上直接创建失败。

清洗只在 `ingest` 阶段生效，不改动用户既有文件——除非用户显式要求重新整理。

## 四、归属判定与兜底目录

- 类型归属不清的资源一律落 `其他/`，**绝不猜测**是电影还是剧集。
  猜错的后果是文件进了错误的分类树，用户下次盘点时找不到。
- 解析不出片名的文件不归档，跳过并在结果里标注，让用户自己决定。
- 归类为 `其他` 的条目在报告里要显式指出来，提示用户可以用 `--type` 重跑一次归档。

## 五、哪些文件会进库、哪些被跳过

**会进度：**视频容器 `.mkv .mp4 .avi .ts .m2ts .mov .webm .wmv .flv .rmvb .mpg .mpeg`；
以及绑定了具体集号的伴生文件 `.srt .ass .ssa .sub .idx .nfo .jpg .jpeg .png`。

**一定跳过：**

| 跳过对象 | 原因 |
|---|---|
| 0 字节文件 | 选集下载会为未选中的文件留 0 字节占位，入库即污染 |
| `*.aria2` | 未下载完成的控制文件，属于临时状态而非内容 |
| 无集号的伴生字幕/图片 | 归属不明，不硬塞进某一集目录 |
| 其它扩展名（readme/url/exe 等） | 不属于媒体内容 |

## 六、归档动作与结果码

`archive_action` 决定用哪种链接方式，默认 `move`（同盘瞬时移动，不额外占空间）：

| 动作 | 行为 |
|---|---|
| `move` | 优先 `rename`；跨设备时 `link` 后删源；都不行才复制 |
| `hardlink` | 建立硬链接，源文件保留；不可用时回退复制 |
| `copy` | 直接复制（受体积闸门约束） |

默认**不覆盖、不删除**。目标已存在时记为 `skipped-exists`，交给用户决定，
不要用「反正内容一样」的理由自动跳过或覆盖。

每条结果都带状态码，读状态码判断成败，不要读自然语言日志：

- `dry-run`、`moved`、`linked`、`skipped-exists`
- `moved-cross-device-link`、`moved-cross-device-copied`
- `hardlink-unavailable-EXDEV+copied`、`hardlink-failed-<errno>+copied`
- `refused-large-copy-<tag>:<size>><阈值>`、`error:<原因>`

遇到 `refused-large-copy` 说明回退复制被体积闸门拦下（默认阈值 2 GiB）。
这时如实告诉用户「目标与源不同文件系统，复制会占用 N GB」，等用户显式放行
（`allow_large_copy`）再执行——绝不为用户默认接受一次大体积复制。

## 七、路径安全边界

所有拼进媒体库的路径都过 `safe_join`，做**两层**断言，缺一层都能被绕过：

1. 文本层：规范化后必须仍在库根之内，挡住 `../` 与绝对路径。
2. 真实层：对库根与目标各取一次 `realpath`，挡住「库内指向外部的符号链接」。

越界直接抛错并中止该条归档，不做「就近修正」或「换个目录放」的处理。
**为什么**：种子文件名是外部可控输入，遇到越界说明这不是正常资源，修正只会掩盖问题。

返回给系统的是 `abspath` 而不是 `realpath`：库根本身可能就是符号链接，
用 realpath 会把用户指定的路径改名，落盘位置就不再是用户要的那一个。

## 八、与清单导出的关系

- 归档完成后，条目写入库索引并导出 `library.json` 与 `LIBRARY.md` 供 agent 读取
  （SQLite 二进制无法直接读）。
- 索引只记录**本地事实**与查询条件（片名/年份/季集/路径/体积/中字标记），
  不保存磁力链接或 info hash——索引库不是资源索引库。
- 文件名与目录结构是索引的**唯一真相来源**，所以规范一旦确定就不要随意变动；
  确有变动时用 `index rebuild --library <库根>` 从磁盘重建，而不是手工改数据库。
