# 中文字幕：三层策略与标记词库

> 何时读：判断某个资源是否真的带中字、用户要特定语种（简中/繁中/双语）、
> 字幕找不到或时间轴对不上、需要向用户解释「为什么这部外语片没有中字版本」。

## 一、三层策略总览

```
第一层  检索期：从资源标题识别中字标记 → 命中即置顶排序
          ↓ 无命中
第二层  下载后：检测内封字幕轨 / 同目录外挂字幕文件
          ↓ 无中字
第三层  补齐期：向字幕站检索并下载，落地到视频同目录
```

三层的**成本递增**：第一层只花一次字符串匹配，第二层要等文件到手，第三层要走网络且
不保证有结果。所以顺序不能颠倒——先在第一层筛掉无中字版本，能省下一次几十 GB 的错误下载。

各内容类型的先验差异（决定该在哪一层多花力气）：

- **动漫**：中文压制/字幕组做种比例高，标题常直接写「简繁内封」「双语」。第一层命中率最高。
- **国产影视**：本身是中文，通常无需补字幕；标题里的标记多用于区分配音（国语/粤语）。
- **好莱坞外语片**：公开源普遍没有中字标记版本，基本必然落到第三层。
  这种情况要**尽早**告诉用户，别让用户等下载完才发现是生肉。

## 二、第一层：标题中字标记识别

**中文字符标记（命中即算带中字）：**

```
中字   中文   简体   繁体   简中   繁中   简繁   双语   中英
国语   國語   粤语   粵語   内封   内嵌   外挂   字幕
```

**拉丁字符标记（大小写不敏感）：**

```
CHS   CHT   GB   BIG5
```

判定时大小写不敏感，并把 `CHS`/`CHT` 这类短标记按词边界匹配——否则
`CHS` 会误命中普通单词中间，产生假阳性。

**常见写法组合：**`简繁内封`、`简繁英双语`、`中英双字`、`CHS&CHT`、`GB/BIG5`、
`[简日双语]`。看到这类组合，直接判为带中字且同时含简繁两种。

**压制组/字幕组名**是较强的旁证：标题里出现 `字幕组`/`字幕組`，或出现已知中文
字幕组、压制组的名字（形如 `XX字幕组` 的署名、`xxx-Raws` 这类压制组尾缀），
都可作为加分依据。组名不是充分条件——**以标记词为主、组名为辅**，不要仅凭组名
就断定带中字。

**不要把「中字」当成片名的一部分**：`中字`、`中文字幕`、`国语`、`粤语`、
`字幕` 等词在提取片名时属于噪声词，必须剥离，否则会让片名解析结果带上后缀，
影响元数据查询与检索命中。

**检索期使用方式：**带中字标记的结果在打分中加最高权重，使「有中字的普通画质片」
稳定胜过「无中字的高清片」。这是刻意的价值排序，不是可调偏好——中文用户的实际
可用性取决于有没有中字。

## 三、第二层：下载后内封/外挂检测

下载落地后，按以下顺序确认是否已有中字，避免重复去字幕站：

1. **同目录外挂字幕文件**：与视频同名的 `.srt` / `.ass` / `.ssa`，
   以及带语言后缀的同名文件（见第七节）。
2. **内封字幕轨**：需要可选的 `ffprobe` 依赖。**没有 `ffprobe` 时如实说明
   「无法确认内封字幕情况」，不要假装检查过。**
3. MKV 封面、章节等附属信息与字幕无关，不作为中字依据。

合集类资源还有一个额外机会：拿到文件列表（`.torrent` 的 bencode 列表）时，
如果列表里出现 `.srt`/`.ass` 文件或标题中带字幕标记，可提前判断这套合集是否
自带中字，从而免去第三层。

## 四、第三层：字幕站补齐

**免密钥通道：**OpenSubtitles 的 legacy REST 接口，检索路径形如
`/search/query-<片名>/sublanguageid-chi`，返回 JSON 数组，每条含字幕文件名、
语言、下载次数与 `SubDownloadLink`。

**调用要点：**

- 查询词**必须先统一转小写**再除了放进 URL：路径里出现大写 ASCII 字符时，
  服务端会 302 到一个 Host 为空的地址，必然解析失败。
- 必须使用**播放器风格的 User-Agent**（如 `TemPlayer v1.0`），否则被拒或返回空。
- 返回的下载链接指向 `.gz`，需 gzip 解压后才是 `.srt`。以 `.gz` magic
  （`1f 8b`）判断而不是靠 URL 后缀。
- 语言用 `chi`（中文字幕的总语言 id）检索。

**拿到候选后不要直接落地**：先按第六节的匹配原则选优；用户明确要简中/繁中时，
要在候选名里核对语种标记，找不到对应语种就如实说明只找到通用中文。

**补不到时给用户的建议（按优先级）：**

1. 换一个带中字标记的片源版本（回到第一层）；
2. 换合集/整季版本碰运气（合集常自带字幕）；
3. 手动补字幕（把字幕文件放到视频同目录，命名与视频一致）。

## 五、字幕文件清洗规则

字幕站的返回正文经常夹带推广行，必须清洗后再落地，否则会随字幕出现在播放器画面里。

**清洗步骤：**

1. 去掉 UTF-8 BOM。
2. 按空行切成块，剔除命中推广特征的块（推广域名、站点自荐语、
   「字幕由 XX 提供」之类署名）。
3. 若整份文件都未命中推广特征，说明清洗已完成，原样保留。
4. **退化情形**：推广行与正文字幕挤在同一块（缺少空行分隔）时，改为逐行剔除，
   保留块内其余行，绝不整块丢弃——整块丢弃会把该时间轴的字幕一起删掉。

**判定清洗成功的标准**：正文汉字的实际占比明显高于推广行占比。若清洗后
正文几乎不含汉字，说明拿到的不是中文字幕，应如实报告而不是当作成功。

## 六、匹配与选优原则

候选字幕按以下顺序筛选：

1. **文件名要含 release 组名或片源版本标识**——字幕与片源版本对齐，时间轴才不容易错位。
2. **优先下载次数高的**——下载量大意味着更多人验证过，是质量的正相关信号。
3. 格式优先 `.srt`（通用性最好）；`.ass` 更适合字幕组特效字幕，但样式依赖字体。
4. 同一片源版本有多个候选时，优先带明确语言标记的那一个。

**不要**把语言不对、格式不明、或文件名与片源版本完全无关的候选落地。宁可报告
「未找到匹配中文字幕」并给出建议，也不要落一份时间轴对不上的字幕让用户自己折腾。

## 七、语言变体与文件命名后缀

字幕文件名常见的语言后缀（大小写不敏感，可带 `.1`、`.2` 之类的序号）：

| 后缀 | 含义 |
|---|---|
| `zh` / `chi` | 中文（不区分简繁） |
| `chs` / `sc` / `gb` / `zh-cn` / `zh-hans` | 简体中文 |
| `cht` / `tc` / `big5` / `zh-tw` / `zh-hant` / `zh-hk` | 繁体中文 |
| `eng` / `en` | 英文 |
| `jpn` / `jp` / `jap` | 日文 |
| `kor` / `kr` | 韩文 |

**为什么需要这张表**：判断「某视频是否已配好中文字幕」时，要先剥掉语言后缀再比对
主名。`Movie.2020.cht.srt` 与 `Movie.2020.mkv` 是配对文件；只做同名比对会漏判，
导致重复下载字幕并覆盖用户已有的文件。

外挂字幕落地时，文件名与视频主名保持一致（必要时带语言后缀），放在视频同目录，
便于播放器自动加载。

## 八、诚实边界

- **外语片的中文字幕不保证存在**，也不保证找到的那份与手上片源的版本一致。
  时间轴错位是常见结果，必须提前告知用户，不能假装成功。
- 下载后才发现是生肉时，如实报告并提供上面三种补救路径。
- 内封字幕在没有 `ffprobe` 的环境下无法确认，报告里要写明「未能确认」，
  不要用「应该没问题」这类表述代替检测。
- 字幕格式与编码无法解析时，报告原始原因（如「解压失败」「编码非 UTF-8」），
  不要静默丢弃后当作「未找到」。
