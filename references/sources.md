## 一、三层源策略

| 层 | 内容 | 默认状态 |
|---|---|---|
| L0 聚合器 | `api.knaben.org/v1`，服务端代为访问多个上游索引站，返回值标明来源 | 启用 |
| L1 公开直连源 | 面向特定索引站的适配器（**必须**带词元校验闸门） | 按需启用 |
| L2 自备源 | 用户自有 PT 站、Jackett、Prowlarr 等 | 默认关闭，需显式配置 |

**聚合器是首选通道**：它解决的正是「本地网络连不上海外索引站」这类可达性问题，
一次请求覆盖多个上游，且中文与拉丁查询都能命中。能用聚合器时就别逐个直连。

## 二、默认源的行为要点

调用聚合器时以下约定必须遵守，否则会拿到 0 条或错字段：

- 请求体字段：`search_field`（固定 `title`）、`query`、`order_by`（`seeders`）、
  `order_direction`（`desc`）、`size`。
- **不要附加 `search_type` 参数**——带上之后接口稳定返回 0 条。
- 结果数组里标题字段是 `title`，活种子数是 `liveSeeders`，体积是 `bytes`，
  来源站是 `tracker`，另有 `magnetUrl`。**没有** `name` 字段。
- 必须带 `User-Agent` 头，否则部分上游返回 403。
- 到手的 `magnetUrl` 自带一批 tracker，可直接交给下载引擎，无需再补。

`query_script` 标记源能处理的查询字符集（`latin` / `cjk` / `both`）。构造检索名时
按目标源的 `query_script` 决定用中文名还是拉丁名——**给只能处理拉丁查询的源喂中文
查询，是产生「结果全不相关」的最主要原因**。

## 三、词元校验闸门

**症状**：查询返回 HTTP 200、JSON 合法、结果上百条、种子数充足，但全部与查询无关
（典型表现是返回该站的「最新上传流」）。这类失败按成功率记分的健康探测完全看不出来。

**规则（优先级高于打分）：**

1. 结果标题必须命中查询词元集合中的至少一个有效词元。
   - 拉丁词元（长度 ≥ 3、非停用词）按词边界匹配；
   - 中文词元整体匹配，失败时退化为任意相邻二字子串匹配。
2. 不命中的结果直接丢弃，并计入该源的**语义失败率**。
3. 明确区分两种空结果：
   - `[{"id":"0","name":"No results returned"}]` 这类 stub —— 源明确说没有；
   - 非空但全被闸门丢弃 —— 源侧退化成「最新上传流」。
   二者要给用户不同的解释与不同的下一步建议。
4. 查询全文为空时闸门放行（无可校验词元），但这类查询本身就不该发起。

闸门是「丢弃」而不是「扣分」：不相关的结果一旦进入候选列表，模型很容易被
种子数迷惑而推荐它。

## 四、结果字段与排序口径

单条结果的标准字段：

| 字段 | 含义 |
|---|---|
| `title` | 资源名原文 |
| `magnet` | 磁力链接（无磁力的结果不产出） |
| `size` | 字节数 |
| `seeders` | 活种子数 |
| `source` | 来源站标识 |
| `category` | 源侧分类 |
| `is_batch` | 是否为合集/整季 |
| `marks` | 从标题识别出的中字等标记集合 |

打分以种子数为基座，再叠加：中字标记（最高权重）、标记数量小幅加分、
画质偏好命中加分；对续集/后续作施加惩罚（故意小于中字权重，使「有中字的续集」
仍能胜出「无中字的正片」）；同种子数下偏好小体积。

向用户呈报候选时按这个顺序解释推荐理由：中字情况 → 种子数 → 体积 → 是否合集。
**不要把续集当成同一部片推给用户**，`is_batch` 为真的合集会下整季，需单独提醒。

## 五、接入自备源

自备源走显式配置，不做自动探测，避免静默改动用户已有的下载客户端与环境。

**通用接入步骤：**

1. 在配置里声明启用：`media.py config --set sources_enabled='["knaben","<你的源id>"]'`。
2. 源需要的凭据（API key / cookie / 用户名密码）通过环境变量或本地配置文件提供，
   **不要**写进 SKILL.md、不要提交进仓库、不要在报告里回显。
3. 用 `doctor sources` 做一次只读探测，确认可达性与 `query_script`。
4. 用一部已知存在的片做冒烟检索，确认结果经过词元闸门后仍有命中。

**Jackett / Prowlarr 类元索引：**把它们当作一个 L1 源适配器接入（两者都提供
JSON 检索接口），在适配器里把返回结果映射到标准字段。注意这类工具返回的标题
同样需要过词元闸门。

**PT 站：**站点规则（ratio、HR、允许的客户端）由用户自行遵守。skill 侧只做检索与
把磁力交给下载引擎，不代替用户处理站点账务，也不做自动化刷流量行为。种子数在 PT
语境下含义不同（做种者数 ≠ 可连接数），呈报时如实标注来源是 PT 站，让用户自己判断。

**代理：**代理是用户显式配置项。空字符串代表「用户要求直连」，不要回退到
读取环境变量——用户清空它就是在表达意图。SOCKS 代理不能传给下载引擎
（详见 `references/troubleshooting.md`）。

## 六、新增源适配器

适配器是仓库里的一个类，需满足 `Source` 接口：

| 属性/方法 | 要求 |
|---|---|
| `id` | 小写短标识，与配置里的 `sources_enabled` 对应 |
| `supports` | 覆盖的内容类型，如 `["movies", "tv", "anime"]` |
| `query_script` | `latin` / `cjk` / `both`，如实填写 |
| `needs_key` / `needs_proxy` | 是否需要凭据、是否通常需要代理 |
| `priority` | 同层源之间的排序权重 |
| `search(query, timeout, proxy, size)` | 返回 `Result` 列表；无磁力的结果直接不产出 |
| `health(proxy)` | 只读可达性探测，异常时返回 `False` 而不是抛错 |

编写要点：

- 解析失败**不要**让整条结果作废：标记与合集判定失败时降级为「无标记」，
  标题与磁力仍然可用。
- 结果里没有磁力链接的条目直接丢弃，不要产出只有种子文件的半成品。
- 网络异常、限流、超时都返回空列表而不是抛错——单源失败不能拖垮聚合查询。
- 新源挂进注册表后即可被 `registry()` 收录；未在 `sources_enabled` 里启用时不会生效。

## 七、源健康与降级

- `doctor sources` 逐个探测启用源的可达性，输出 `id` / `reachable` / `query_script`。
- 聚合查询对单源失败静默跳过，健康度由 `doctor` 统一上报——**不要**因为一次
  检索少了几条结果就断定某个源坏了，先跑 `doctor sources`。
- 源不可达时先确认网络与代理，再考虑换源；连续空结果且闸门丢弃率极高时，
  按「源语义退化」处理并如实告知用户。
- `doctor regrab` 只产出「库里有、当前条件检索不到候选」的清单和原因，
  **不执行任何获取动作**。实际重下必须逐条获得用户确认。

## 八、贡献规范与拒绝清单

**接受的贡献：**

- 新的源适配器，符合上面的接口与降级要求。
- 提高词元闸门准确率的规则改进（附能复现的反例）。
- 结果字段映射修正、超时与重试策略改进。

**不接受：**

- 批量抓取器、站点爬虫、HTML 解析式抓取（只调第三方 API）。
- DRM 绕过、付费墙绕过。
- 把本工具变成公开索引服务的改动（服务端接口、公开查询页、共享链接池）。
- 提交任何真实站点的密钥、cookie 或账号信息。

新增源时同步更新本文件的源清单表，并在提交说明里讲清：源解决了什么可达性/语种
问题、`query_script` 判断依据、以及一次成功检索的实际返回样例。
